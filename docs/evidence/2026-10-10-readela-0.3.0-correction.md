## What was corrected

### Saved place

- **Identity.** `conversationId` takes the identifier from the address path by
  the adapter's patterns; `conversationKey` fingerprints it with the site's
  id. The first implementation fingerprinted the host and the whole path, so
  one conversation under two routes was two conversations.
- **Anchor.** A place records the fingerprint of the turn identifier the site
  gives the response (or, without one, of the whole response), the block's
  kind, fingerprint and position in its response, its two neighbours'
  fingerprints, the row number where the site gives one, and a coarse
  position. See `docs/architecture.md`.
- **Matching.** `locatePlace` looks only inside the response the place was
  saved in. Identical text elsewhere is never a candidate; several identical
  blocks in that response need exactly one whose neighbours agree; an
  approximate place needs an identified response and both neighbours. The
  first implementation took the nearest block with the same text anywhere on
  the page.
- **Recovery.** On Return only, a response that is not in the document is
  searched for in the conversation's scrolling region. Limits, chosen from the
  implementation and the checks: 40 stops and 12 seconds in all; a stop waits
  at least 120 ms, up to 360 ms for a first change, then for 100 ms without a
  change, at most 700 ms; after five stops that bring nothing new only the two
  ends are tried; arrival is confirmed within 2.5 seconds. On the synthetic
  long conversation (60 rows, about 12,000px, rows entering 40 ms after a
  scroll) a place 20 rows away was reached each time; a search for a response
  that never enters the document ended after about 4.2 seconds in both
  browsers.
- **Persistence.** `changeMarks` reads, changes one entry, writes and reads
  back; the reader updates what it holds and shows only from that answer. The
  first implementation updated the page first and wrote the whole collection
  it held.
- **Targeting.** Readable blocks of responses only; a block kept for screen
  readers (smaller than 3px, or not visible) is not readable; the block is the
  one holding a selection in view, otherwise the first at the top of the
  reading area that a point test finds uncovered.
- **Stored format.** `readela.marks` version 2. Version 1 existed only in the
  owner's local review build; its entries are dropped when read, so a place
  saved with that build has to be saved again.

### Reading surfaces and semantic content

- Adapters name `scope`, `conversation`, `scroller`, `user`, `prose`,
  `capsule`, `turn` and `order`. The surface is the `prose` root and nothing
  else; the first implementation took the parent of any reading block.
- The conversation shown is the rendered `scope` element. A one-second check
  catches the site showing a conversation it kept, which changes no element.
- Units that stay the site's are marked with what they need (`surface`,
  `round`, `text`); a unit with an opaque background and a colour of its own
  gets no rule. The rule that gave every `pre` the site's background is gone.
- `colourAlpha` reads opacity from the alpha value only. The first
  implementation's pattern matched any colour ending in `, 0)`.
- New tokens: `muted` (secondary text and list markers) and `quote` (the bar
  of a quotation); highlighted text uses the selection pair. Borders are
  recoloured on tables and quotations only.

  | | Paper | Night |
  | --- | --- | --- |
  | Secondary text | `#4F473C` | `#C4BBAC` |
  | Quotation bar | `#7D6F59` | `#9A8E7C` |

  | Contrast ratio | Paper | Night |
  | --- | --- | --- |
  | Secondary text on surface / inline code / table header / saved block | 7.97 / 7.08 / 7.28 / 7.09 | 8.43 / 7.09 / 7.49 / 7.11 |
  | Quotation bar on surface / saved block | 4.27 / 3.80 | 4.98 / 4.20 |

  The other palette values are unchanged.

### Popup

- Order: Appearance, Font, Text size, Line spacing, Text direction, Saved
  place, Reset, footer.
- Selected: a raised segment with a 1px outline in the text colour and weight
  650; no underline. Focus: a 3px ring in the accent colour. Off: muted text
  at full opacity with the selected segment outlined in dashes.
- Saved place: Save place or Update place, Return, Clear; the guidance line;
  status messages worded after the fact.
- Reset: an outlined button. Footer: "By Amir42" with the link, and "Version
  0.3.0".
- **Direction control.** Kept as a segmented control. Reasoning: the four
  choices are short, the other four settings use the same control, the
  selected choice is visible without opening anything, one press changes it,
  and its keyboard and assistive behaviour was already checked. A select
  would hide three of four choices and add a second kind of control for no
  gain in space: moving the group below the other settings is what puts
  reading first.

## Typography

visible choices stay. The choice of a Latin face remains open for the owner's
visual judgement.

Night surfaces, at one and two device pixels per CSS pixel, with the same
English, Persian, mixed and Arabic paragraphs, a list, emphasis, strong text,
numerals and 13px text:

Sources: Vazirmatn `v33.003` from the official `vazirmatn@33.0.3` package
(`Vazirmatn[wght].woff2`, SHA-256
`4e3fa217d38fdafc1fea4414ceb58ca5e662cf0ab5fa735a8c8c20e8b42cad92`; its
`OFL.txt` has the digest of the packaged licence). The Inter file was a Latin

`2c295d99e26dcf357d4d01bcf270fd6924b600c9a13dd8c363ef114f4c6976fa`); its

What was seen: Persian and Arabic text is the same in all three. The English
text differs in flavour, not in ease of reading: all three are even and clear
at 16px and at 13px. A keeps real italics and the hinting of the platform's
own font. B and C lose real italics and add 63 KB or at least 73 KB to a 78 KB
package; their one clear gain is that Latin text would look the same on every
platform. That was not judged a material reading benefit worth the size, a
second third-party asset and its provenance work, so nothing was changed.

## Findings and their disposition

- **Fixed in this work**, beyond the corrections above: the reader's own
  message on ChatGPT is given a direction again (the selector for it had
  stopped matching; carried from the first implementation's evidence).
- **Accepted limits, recorded in the README.** A place can be saved in a
  response, not in the reader's own message. A place whose response was
  regenerated or removed is reported as not found and stays saved. A paragraph
  with an identical twin beside it and identical neighbours cannot be saved.
  Return gives up after about twelve seconds. Two tabs that both save within
  the same few milliseconds can still interleave their writes. The saved place
  is not announced in the page to a screen reader.
- **Carried to the store-presentation work (ENT-243), not changed here by the
  owner's instruction.** `docs/store-listing.md` and the manifest
  `description` still say "reading mark", "Mark here" and "Go to mark", and
  the listing's data notes describe the first stored format; the listing
  images show the 0.2 popup. Revisit trigger: the owner's approval of the
  corrected build, before any 0.3.0 submission.
- **Carried, repository only.** `scripts/store-images.mjs` was neither run
  nor changed. It frames the test conversations and the popup for the earlier
  layout and is revised with ENT-243.

No wide-audit trigger fired: the change is confined to the declared scope, no
permission, match pattern, web-accessible resource or network request was
added, and its trust-relevant parts (the stored record, when the page is
scrolled, the popup's link) are covered by the targeted checks named in the
Preflight Record.
